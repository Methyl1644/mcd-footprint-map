# 本次新增了什么？为什么需要？

先说明「本次新增」这个词在页面里有两个语境，下面分别解释，避免混淆。

---

## 一、界面上的「本次新点亮」指什么

页面顶部在有时会出现一条金色提示：**「本次新点亮 N 座城市」**，下面列出城市名，
地图上这些城市的点位是金色且带脉冲圈的。

**它指的是**：和**上一次查看**相比，这一次多出来的城市。

判定规则（`src/mcd_footprint/aggregate.py`）：

| 情况 | 判定方式 |
| --- | --- |
| 有历史状态文件（`--state out/state.json`） | 严格差集：`这次的城市集合 − 上次记录的已知城市` |
| 首次运行、没有历史可比 | 退化为「最近 30 天内首次到访」的城市 |

**作用**：让"我又解锁了一座城"这件事被看见。足迹地图的意义在于积累，
如果每次打开都是一堆同样的点，就感受不到进展。

**为什么需要它**：`order-list` 没有分页、只返回有限条历史（实测 10 条），
单纯看"点亮了多少城"是静态的；只有做差集，才能表达"**新增**"这个时间维度上的变化。

## 二、本轮改动新增了什么

下面每一项都按「是什么 / 作用 / 为什么需要」说明。

### 1. MCP_TOKEN 可配置（设置面板）

**新加的东西**

- 页面右上角新增按钮 **⚙ 设置 Token**，点击弹出设置面板
  （输入框 + 显示/隐藏 + 状态行 + 保存/清除）。
- 后端新增：
  - `src/mcd_footprint/config.py` —— Token 的本机持久化（读写、脱敏、清权限）
  - `src/mcd_footprint/server.py` —— 本地服务与 4 个接口
  - `src/mcd_footprint/pipeline.py` —— 抽出的公共流水线，CLI 与服务共用
  - CLI 新增 `--serve / --host / --port / --no-open / --save-token / --show-token / --clear-token`
- 接口：`GET /api/state`、`POST /api/token`、`DELETE /api/token`、`GET /api/footprint`、`POST /api/refresh`

**作用**

保存 → 服务端持久化 → **立刻用新 Token 重新取数** → 页面刷新，
「保存」和「生效」是同一次操作。反馈分三种：

| 结果 | 页面提示 |
| --- | --- |
| 保存成功且取数成功 | `✓ 保存成功：abcd****2345` + 底部 Toast「正在重新加载你的足迹…」→ 自动刷新 |
| 保存成功但取数失败 | `✓ 保存成功，但取数失败：MCP HTTP 401（Token 无效/过期）` —— 保留上次数据不丢 |
| 未填写 | `请先填写 MCP Token。` |

**为什么需要它**

- 原方案只有 `export MCD_MCP_TOKEN=...`，换账号/换 Token 要回到命令行重跑，
  对"只是想看看自己足迹"的人门槛太高。
- 产物 HTML 是**静态单文件**，浏览器无法直连 `https://mcp.mcd.cn`
  （跨域 + 需要 Bearer 鉴权）。所以必须由本机服务代持 Token 代为调用，
  浏览器只和 `127.0.0.1` 通信。
- 安全边界：仅监听 `127.0.0.1`；`/api/state` 只返回 `abcd****2345` 这种脱敏串，
  任何接口都不回传明文；Token 落在 `~/.mcd-footprint-map/token.json`（权限 600），
  **不会写进产物 HTML**，因此产物可以放心分享。
- 离线双击打开 HTML 时，设置面板会明说"当前是离线静态页面，无法直连 MCP"，
  暂存到浏览器本地，启动服务后自动同步——不假装能用。

### 2. 城市 → 订单的两级联动（默认只展示城市）

**新加的东西**

- 右栏新增 **「已点亮城市」列表卡片**（默认视图）。
- 「城市订单」与「日期时间轴」两个区域改为**空态引导**：
  未选城市时显示"先选一座城市"，不铺任何订单。
- 交互路径：点城市 → 显示该城市的**订单 + 门店列表 + 该城市的日期**；
  再点某家门店 → 二级筛选，只看这家店。
- 新增界面元素：`← 返回全部城市`、"正在查看：城市 / 门店"筛选条。

**作用**

把"几百条订单一次铺开"改成"按城市下钻"。默认信息量从 N 条订单降到 N 座城市，
首屏可读；想看细节再点进去。

**为什么需要它**

- 足迹地图的主角是**城市**，不是流水。默认铺订单会盖过地图本身。
- 原实现默认展开"今天"的全部订单，城市与订单的主次是反的。
- 也顺带解决了一个真实问题：同一天可能在多个城市有订单，
  不按城市筛选时，"这天吃了什么"其实是错的。

### 3. 定位逻辑的补齐与自检

**新加的东西**

- `src/mcd_footprint/cities.py`：新增 **L1b 门店名包含式纠偏**
  （`storeNames` 支持子串匹配，取最长键），修正了与实际代码不符的降级链注释。
- `narrative.py`：每条订单新增 `city_source`、`store_code` 字段。
- `aggregate.py`：门店对象新增 `city_source` 字段。
- 订单详情新增「定位：门店名 / 门店地址 / 人工纠偏 / MCP 反查」标签。
- 页面底部新增「定位逻辑」说明与「待确认 N 条」提示。
- 新增 `tools/audit_geolocation.py` 体检脚本。

**作用**

每条订单都能回答"这座城市是怎么判断出来的"，无法判定的会被单列出来而不是悄悄丢掉。

**为什么需要它**

- 定位链路是"订单 → 门店 → 门店名/地址匹配城市"，是**推断**不是接口直给，
  必须可追溯，否则错了没法纠。
- 无法定位的订单原本只进 `unresolved` 数组，界面上看不见，用户会以为"漏了"。
- 体检脚本实测结果（本轮跑过）：

  | 数据源 | 可定位 | 来源分布 |
  | --- | --- | --- |
  | 示例数据（58 单） | 58/58 = 100% | 门店名 100% |
  | 真实 MCP（10 单） | 10/10 = 100% | 门店名 70%、人工纠偏 30% |

  两组都是 100%，且所有城市都有经纬度。**结论：定位功能已完整可用。**

### 4. 克制的视觉装饰

**新加的东西**（全部是静态样式，无新增动效）

- 顶部 3px 品牌细条（红）+ 1px 黄线
- 主标题下 26×3px 色块
- 卡片标题左侧 3px 色条（红 / 黄 / 灰，用于区分层级）
- 列表行（城市 / 门店 / 日期）悬停与选中时的左侧色条 + 极浅底色
- 时间轴上"今天"的红色小标签

**同时删掉的**

- 统计条与「今天」卡片的渐变填充，改为单色。

**为什么需要它**

原界面所有卡片是同一层级的白底，看不出主次。加装饰的目的是**建立层级**：
页面头 → 地图 → 城市列表 → 订单。颜色只用已经存在的品牌红/黄和中性灰，
不引入新色相，不加渐变，不加装饰性动画——唯一保留的动效是"新点亮城市"的脉冲圈，
它本身承载信息（表示"这是新解锁的"），不是装饰。

### 5. 第三轮：时间轴瘦身、追问恢复、Token 接入引导、界面截图

**新加 / 改动的东西**

| 改动 | 说明 |
| --- | --- |
| 时间轴改为纯日期索引 | 每行只留「日期 + 星期 + N 单 + 今天/深夜标记」，去掉与《城市订单》重复的门店名与菜品预览 |
| 深夜追问回到时间轴 | 有深夜记录的日期，行内显示该日追问的预览（浅色斜体），点开即当日完整回忆 |
| 追问样式 | 当日回忆中的追问前加 🌙，文案改斜体 |
| Token 接入引导 | 离线页面设置面板给出**两条完整路径** + 可一键复制的命令：路径 A 启动本地服务在页面填写；路径 B 命令行保存后进重新生成页面 |
| `--save-token` 交互化 | 不带参数时提示输入（终端内不回显，管道场景退化为读一行），保存后打印下一步命令 |
| 界面截图 | `docs/images/screenshot-overview.png`（默认视图）、`screenshot-detail.png`（城市+深夜日期下钻） |
| 视觉微调 | 字体栈补 HarmonyOS Sans SC/MiSans；卡片阴影与圆角、按钮阴影与圆角、滚动条、卡片标题字距；统计卡首卡用品牌红数字 + 顶部黄色短条；地图省份悬停淡橙；表单控件圆角；追问与卡片间距 |

**为什么需要这些改动**

- 时间轴与《城市订单》原本都展示「门店 + 菜品」，信息重复。改为**索引 / 内容**分工后，
  时间轴负责"哪天去过、有没有深夜场"，点击后右侧才是当天的完整回忆。
- 深夜追问此前**并未丢失**（18 条深夜记录全部带追问，详情页也渲染），
  但它藏在"选城市 → 再选中有深夜的那个日期"两层操作之后，几乎不会被看到。
  把它提到时间轴行内预览后，这个功能才真正可发现。
- 双击打开静态 HTML 且浏览器禁用本地存储时，原提示是一句"无法暂存"的死胡同。
  现在面板直接给出可复制的两条路径，Token 一定可以设置成功。
